# Резервная одометрия трамвая по модели — ROS 2 Humble

Пакет `tram_backup_odometry` оценивает **продольную скорость и положение** трамвая в реальном времени только по
`/vehicle/front_bogie_velocity`, `/vehicle/rear_bogie_velocity` и `/vehicle/driver_position_cmd`.
GNSS используется **только для начальной выставки** в первые секунды. После выставки подписки на GNSS
уничтожаются, в журнале это видно строкой `GNSS-подписки закрыты`.

> В решении для жюри эта модель работает внутри ноды `tram_odometry` (корневой README ветки `main`,
> `docs/REPORT.md`): там свои имена выходных топиков, параметры модели задаются как `model.*`
> в `src/tram_odometry/config/params.yaml`, а редкие точки GNSS в середине маршрута используются
> для коррекции положения. Ниже описана собственная нода модели.

Встраивание расчётного ядра в другое ROS-окружение и приёмочные тесты — `docs/INTEGRATION.md`.

## 1. Сборка

Требования: Ubuntu 22.04 и ROS 2 Humble (`ros-humble-ros-base`, `ros-humble-rosbag2`), `python3-numpy`.
Интернет при сборке не нужен.

Пакет собирается в одном workspace с пакетом сообщений организаторов `tram_vehicle_msgs`. Своей копии
этого пакета в репозитории нет: он берётся у организаторов (стенд `check-code` или датасет).

```bash
# в workspace с src/tram_vehicle_msgs организаторов
source /opt/ros/humble/setup.bash
colcon build
source install/setup.bash
colcon test --packages-select tram_backup_odometry && colcon test-result --verbose
```

> ⚠️ Исходный `tram_vehicle_msgs/package.xml` из датасета **не собирается** на стоковом Humble: в нём нет
> обязательного тега `<maintainer>`, и catkin_pkg выдаёт `InvalidPackage`. У организаторов в стенде `check-code`
> этот тег уже есть.

## 2. Запуск на rosbag

```bash
# терминал 1 — нода (+ замер задержки и онлайн-метрики по GNSS-эталону, по желанию)
ros2 launch tram_backup_odometry backup_odometry.launch.py monitor:=true eval:=true

# терминал 2 — воспроизведение прогона
ros2 bag play data/30618_01f73500
```

После остановки bag (Ctrl+C в терминале 1) ноды печатают итоги:

```
[latency_monitor] ИТОГ: n=1630, задержка p50 0.57 мс, p99 1.08 мс, max 1.37 мс, >100 мс: 0; CPU ср. 2.8%; RSS max 66.1 МБ
[online_eval]     ИТОГ v: RMSE … MAE … bias … м/с || pos: гориз. RMSE … | along RMSE … | cross RMSE … | текущая ошибка … % от … м
```

Только нода, без вспомогательных: `ros2 run tram_backup_odometry odometry_node`.

## 3. Выходные топики

Решение публикует выход на **каждое входное сообщение** с новым stamp (около 30 Гц, скорость и положение с одной меткой).
На «запоздавшие» сообщения из очереди рекордера в начале bag тоже публикуется выход с их stamp, чтобы у эталона
не было пропусков.
`header.stamp` = stamp соответствующего входного сообщения, скопированный без изменений.

| Топик | Тип | Содержимое |
|---|---|---|
| `/result/velocity` | `tram_vehicle_msgs/VelocitySensor` | `velocity` — продольная скорость, **м/с**; `frame_id=base_link` |
| `/result/position` | `nav_msgs/Odometry` | `pose.pose.position` — точка **base_link** (ось вращения первой тележки на уровне рельса) в **плоских координатах MGRS**, как у судьи: x = UTM 37N восток − 300 000, y = север − 6 100 000 (квадрат 37U CB, без переноса через границу квадратов), z — эллипсоидальная высота рельса, м; `orientation` — курс касательной к пути в сетке UTM; `twist.twist.linear.x` — продольная скорость; `pose.covariance` — вдольпутевая/поперечная неопределённость в осях x/y; `twist.covariance[0]` — дисперсия скорости; `frame_id=map`, `child_frame_id=base_link`. До первого фикса GNSS (доли секунды в начале) положение не публикуется |
| `/result/geo` | `sensor_msgs/NavSatFix` | та же оценка положения в WGS-84 (lat/lon/alt), `status=NO_FIX`, потому что это не измерение GNSS |
| `/result/slip` | `std_msgs/Bool` | флаг проскальзывания (боксование или юз) |
| `/result/acceleration` | `geometry_msgs/AccelStamped` | `accel.linear.x` — оценка продольного ускорения, м/с² |
| `/result/diagnostics` | `diagnostic_msgs/DiagnosticArray` | 1 Гц: режим, ускорение, флаг и вид проскальзывания, коэффициент скольжения колеса, использованное сцепление a/g, число работающих тележек, сбой датчика (залипание, выброс, аномально высокая дисперсия), удельная сила привода, момент и обороты вала двигателя, ребро и координата вдоль пути по карте, оценённый шум колёс, поправка масштаба, число коррекций по остановкам, число переустановок ветки на стрелках (`branch_switches`), σ положения, время обработки p50/p99 |

Смотреть: `ros2 topic echo /result/diagnostics`, `ros2 topic hz /result/velocity`.

## 4. Режимы положения

1. **`map`** (основной). По GNSS первых ~2 с определяются точка base_link и курс. Используется tf антенн
   от организаторов: master x = −9.873, rover x = +2.563, обе на z = +3.0 м над base_link. Отсюда
   base_link = master + 0.794·(rover − master), по высоте −3.0 м. Курс — направление master→rover, поэтому
   он известен даже на стоянке. Затем точка привязывается
   к карте пути `data/pathgraph.json`, положение = точка карты на пройденном пути s. На стрелках выбирается
   ветка с наибольшей плотностью проездов. На остановках s корректируется по известным местам остановки.
2. **`approach`**. Старт вне карты, например на внутреннем пути разворотного кольца, но рядом с известным путём
   выезда (`data/approach_tracks.json`, строится по данным `tools/build_approach.py`). Положение идёт по пути
   выезда, а в точке въезда переходит на карту.
3. **`dead_reckoning`**. Старт вне карты и без пути выезда: p₀ + s·(cos ψ₀, sin ψ₀). Перед этим привязка
   к карте повторяется с радиусом 24 м по курсу: в части прогонов GNSS смещён на 10–20 м параллельно пути.
4. **`relative`**. GNSS за 15 с не пришёл, или курс неизвестен и привязки нет: относительная одометрия
   от стартовой точки (x = s).

Если у master в начале нет решения status=2, а у rover есть, base_link берётся по rover со сдвигом −2.563 м вдоль пути.

Система координат по умолчанию — `origin: mgrs`, она совпадает с эталоном стенда организаторов
(`/localization/kinematic_state`). Для отладки есть
`origin: first_fix` (ENU от первого фикса) и `fixed`. Карта пути `data/pathgraph.json` построена по данным
и сверена с картой организаторов (Щукинская ↔ Таллинская): поперечное расхождение −0.02 м (p5…p95
от −0.09 до +0.08), по высоте +0.1 м. Наша карта дополнительно покрывает разворотные кольца и съезды.

## 5. Параметры (`config/params.yaml`, секция `estimator.*`)

В ноде `tram_odometry` те же параметры задаются с префиксом `model.` (например, `model.mass_kg`).

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `use_map` | true | положение по карте пути (иначе прямолинейное счисление) |
| `origin` | mgrs | система координат выхода: `mgrs` (UTM 37N − угол квадрата 37U CB, как у судьи), `first_fix` (ENU от первого фикса), `fixed` |
| `master_x`, `rover_x`, `antenna_z` | −9.873, 2.563, 3.0 | tf антенн в base_link |
| `init_window` | 2.0 с | сбор фиксов для выставки |
| `init_timeout` | 15 с | без GNSS → относительная одометрия |
| `gate_sigma`, `gate_min` | 3σ, 0.35 м/с | гейт отбраковки показаний колёс |
| `slip_accel_margin` | 0.5 м/с² | выход ускорения колеса за физическую огибающую → проскальзывание |
| `frozen_n` | 5 | одинаковых показаний подряд в движении → залипание датчика |
| `reaccept_s`, `reaccept_max_s` | 3 / 8 с | ресинхронизация по колёсам при долгом расхождении с моделью |
| `stop_correction`, `stop_sigma` | true, 1.5 м | коррекция по местам остановок |
| `stop_window_max` | 30 м | окно поиска остановки: около длины вагона, чтобы стоянка в очереди за другим трамваем не притягивалась к платформе |
| `reaccept_quick_s` | 1 с | быстрый возврат к колёсам, если невязка физически не может быть проскальзыванием: колесо быстрее модели без тяги или медленнее без торможения, тележки согласованы |
| `scale_adapt` | true | адаптация масштаба колёс по коррекциям (±1.5 %) |
| `fork_select` | true | выбор ветки на стрелке по профилю скорости после неё (`data/branch_profiles.json`) |
| `fork_min_m`, `fork_llr`, `fork_fit_max` | 30 м, 6, 3 | решение не раньше 30 м после узла; перевес логарифма правдоподобия ≥ 6; средний z² профиля выбранной ветки ≤ 3 |
| `init_scatter_max` | 0.2 м | rover с разбросом фиксов на стоянке больше этого (и > 3× master) для выставки не берётся, даже со status=2 |
| `q_accel`, `r_wheel` | 0.2 м/с², 0.05 м/с | шумы фильтра (шум колёс оценивается онлайн по разности тележек) |
| `filter` | kf | основной фильтр — Калман с отбраковкой; `imm` — IMM из трёх UKF (норма/боксование/юз), опция: лучше в смешанных сбоях, хуже без сбоев |
| `use_esn` | true | эхо-сеть в модели динамики (`config/esn.json`, параметр ноды `esn_file`); поправка действует, когда колёсам не верим |
| `init_x`, `init_y`, `init_yaw` | NaN | начальная позиция без GNSS (MGRS, рад): последняя известная до отказа навигации / стартовая точка |
| `mass_kg`, `wheel_radius_m`, `gear_ratio`, `drive_efficiency`, `n_motors` | 42000, 0.33, 7.0, 0.95, 1 | пересчёт удельной силы привода в момент и обороты вала (диагностика); на v и s не влияют |
| `rot_mass_factor` | 0.26 | γ — инерция вращающихся масс (из данных: k_i = g/(1+γ)) |
| `adhesion_mu` | 0.3 | ограничение по сцеплению: \|a\| ≤ μ·g |
| `noise_warn` | 0.3 м/с | шум колёс выше — диагностика «аномально высокая дисперсия» (`high_variance`) |
| `bias_limit` | 0.0 | смещение модели в фильтре (отключено — роль адаптации выполняет ESN) |

Параметры модели привода (масштаб колёс, характеристика тяги и торможения, задержка, инерционность,
коэффициент уклона) получены офлайн-калибровкой (`tools/calibrate.py`) и лежат в `config/model.json`.
Их можно заменить параметром ноды `model_file`, карту — параметром `map_file`.

## 6. Ресурсы и надёжность

- Python/rclpy, один поток. Обработка одного сообщения ≈ 0.1 мс, сквозная задержка p99 ≈ 1.2 мс (максимум < 30 мс), CPU ≈ 3 % одного ядра при ×1, RSS ≈ 66 МБ без роста. Подробно — `reports/VALIDATION.md`.
- Нода не падает на некорректных данных: NaN/inf, отрицательные и огромные скорости, позиции вне −15…15,
  пропуски, сообщения не по порядку. Ошибка внутри оценщика даёт запись в журнал и сброс состояния.
- Скачок времени назад больше 10 с (перезапуск или `--loop` bag) сбрасывает оценщик и повторяет выставку.
- Если входы пропали, до 2 с публикуется экстраполяция с постоянной скоростью; состояние при этом не портится.
