# Резервная одометрия трамвая (ROS 2 Humble)

Решение кейса «Резервная одометрия по модели» Хакатона Московского транспорта.
Нода `tram_odometry` в реальном времени оценивает продольную скорость и положение трамвая
только по датчикам скорости тележек и положению ручки контроллера водителя и публикует
`/result/velocity` и `/result/position`.

## Состав репозитория

```
src/
├── tram_vehicle_msgs/   пакет сообщений организаторов (копия; добавлен тег maintainer — см. ниже)
└── tram_odometry/       нода, ядро, предобработка входов, оценщики, карта маршрута и привязка
                         по GNSS, launch, параметры (config/params.yaml), карта (config/route_map.csv), тесты
tools/
└── build_route_map.py   сборка карты маршрута из GNSS обучающих прогонов (офлайн)
```

## Требования

- Ubuntu 22.04, ROS 2 Humble (достаточно `ros-humble-ros-base`), `python3-colcon-common-extensions`.
- Сторонних Python-библиотек нет — только стандартная библиотека и пакеты ROS 2.
  Интернет для сборки не нужен (проверено сборкой в изолированной сети).

## Сборка

```bash
source /opt/ros/humble/setup.bash
mkdir -p ~/ws/src && cd ~/ws/src
git clone https://github.com/KroLor/respos.git
cd ~/ws
colcon build
source install/setup.bash
```

> Пакет `tram_vehicle_msgs` уже входит в репозиторий. Не копируйте в тот же workspace
> версию из датасета: colcon остановится с ошибкой о дубликате пакета (к тому же версия
> из датасета в Humble без правки не собирается — см. «Отличия от файлов организаторов»).

## Запуск

Терминал 1 — нода:

```bash
source ~/ws/install/setup.bash
ros2 launch tram_odometry tram_odometry.launch.py
```

Терминал 2 — воспроизведение прогона:

```bash
source ~/ws/install/setup.bash
ros2 bag play <путь_к_bag> --delay 3 --clock 100
```

- `--delay 3` — пауза перед первой публикацией, чтобы подписки ноды успели обнаружить
  плеер (DDS). Без неё первые сообщения, в том числе GNSS первых секунд, могут теряться.
- `--clock 100` нужен только для измерения задержки (см. ниже). Нода от `/clock` не зависит:
  метка каждого результата — метка входного сообщения, поэтому работает любая скорость
  воспроизведения (`--rate`).

Аргументы launch: `params_file:=<файл>` — свой файл параметров; `estimator:=<имя>` — другой
оценщик; `use_sim_time:=true` — время ноды из `/clock`.

## Выходные топики

| Топик | Тип | Содержимое |
|---|---|---|
| `/result/velocity` | `tram_vehicle_msgs/msg/VelocitySensor` | `velocity` — продольная скорость, м/с; `header.stamp` — метка входного сообщения; `frame_id` = `base_link` |
| `/result/position` | `nav_msgs/msg/Odometry` | `pose.pose.position` — x, y, z в метрах (`frame_id` = `map`, `child_frame_id` = `base_link`); ориентация — курс; `twist.twist.linear.x` — продольная скорость; ковариации: положения — неопределённость вдоль и поперёк пути, повёрнутая в оси x/y по курсу (откалибрована по данным: скорость σ ≈ 0,1 м/с, путь ≈ 0,6 % пройденного), крен и тангаж малы (рельсы), курс и поперечная ошибка честно велики, пока курс неизвестен |
| `/result/acceleration` | `geometry_msgs/msg/AccelStamped` | продольное ускорение, м/с² |
| `/result/slip_detected` | `std_msgs/msg/Bool` | признак проскальзывания, юза или сбоя датчика колёс |
| `/result/slip_ratio` | `std_msgs/msg/Float64` | продольное скольжение `(v_колеса − v_трамвая) / v_трамвая`: > 0 — буксование, < 0 — юз (наибольшее по модулю из тележек; публикуется, когда есть свежие данные колёс) |
| `/diagnostics` | `diagnostic_msgs/msg/DiagnosticArray` | состояние входов, оценщика и выхода, 1 Гц |

Результат публикуется на каждое сообщение контроллера (~20 Гц; датчики колёс дают только
~9,4 Гц). Если контроллер молчит дольше 0,15 с — на сообщения колёс. Метки результатов строго
возрастают.

## Проверка работы: частота, задержка, логи, диагностика

| Что | Команда | Ожидаемо |
|---|---|---|
| Частота публикации | `ros2 topic hz /result/velocity` | ≈ 20 Гц |
| Задержка «вход → результат» (плеер с `--clock 100`) | `ros2 topic delay -s /result/velocity` | average delay ≈ 0,006 с (точность ограничена шагом `/clock`, 10 мс) |
| Результат | `ros2 topic echo /result/position --once` | заполненный `Odometry` |
| Диагностика | `ros2 topic echo /diagnostics` | по входам: принято / отброшено с причинами, пропуски, возраст данных; оценщик: активный, сбои, проскальзывание; выход: частота, время обработки в ноде, мс |
| Лог ноды | терминал с `ros2 launch` | раз в 5 с — скорость, путь, счётчики входов; предупреждения о сбоях данных |
| Запись для сравнения с эталоном | `ros2 bag record /result/velocity /result/position /diagnostics` | — |

Нода не падает на некорректных данных: NaN и значения вне диапазона, нулевые, повторные и
сбитые метки времени отбрасываются с учётом в `/diagnostics`; при сбое основного оценщика
результат выдаёт запасной, после окончания аномалии оценка восстанавливается.

## Параметры

Все параметры с пояснениями — в [`src/tram_odometry/config/params.yaml`](src/tram_odometry/config/params.yaml).
Основные:

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `estimator` | `wheel_baseline` | оценщик скорости и положения (`gnss_passthrough` — только для отладки конвейера) |
| `vehicle_id` | `30618` | трамвай: выбирает откалиброванный масштаб колёс (см. ниже) |
| `wheel_speed_scale` | 0,0 | множитель км/ч → м/с вручную; 0 — откалиброванный для `vehicle_id` |
| `bogie_mismatch_kmh` | 3,0 | расхождение тележек, после которого измерение подозрительно |
| `suspicious_accel` | 3,0 | изменение скорости колеса быстрее (м/с²) — подозрительно |
| `wheel_timeout` | 0,5 | измерение старше (с) считается устаревшим |
| `driver_cmd_timeout` | 0,15 | молчание контроллера (с), после которого триггер — колёса |
| `wheel_hold_max`, `wheel_decay_tau` | 2,0 / 5,0 | поведение без данных колёс: удержание, затем плавное снижение |
| `wheel_time_alignment`, `speed_time_offset` | `true` / 0,0 | синхронизация по времени: измерение колёс (оно старше метки результата на 40–150 мс) пересчитывается по ускорению на метку результата; убирает смещение скорости на разгоне и торможении |
| `frame_id`, `child_frame_id` | `map`, `base_link` | системы координат результата |
| `route_map_file` | `""` | карта маршрута; пусто — карта из пакета, `none` — без карты |
| `reference_antenna` | `master` | приёмник GNSS для начала координат и привязки к карте |
| `gnss_correction`, `gnss_correction_interval` | `true` / 1,0 | коррекция положения по редким точкам GNSS в пути |

## Положение: карта маршрута и привязка по GNSS

Трамвай ходит по одному маршруту между разворотными кольцами у Щукинской и у Таллинской и не
ездит задним ходом. Поэтому положение определяется как точка на известном маршруте:

1. **Карта** (`config/route_map.csv`) — замкнутое кольцо маршрута (~11 км, точки через 1 м:
   широта, долгота, высота) в порядке движения. Собрана офлайн `tools/build_route_map.py` из
   координат GNSS обучающих прогонов трамвая 30618 (RTK): выбирается лучший прогон каждого
   направления, начало и конец продлеваются по другим прогонам (места стоянки на конечных
   разные), выбросы GNSS отфильтровываются. Проверка: медианное расстояние точек всех
   прогонов до карты — 0,02 м; длина карты совпадает с путём прогонов (медиана 0,01 м на 500 м).
2. **Начальная выставка** (первые секунды прогона, когда GNSS гарантирован): начало координат
   результата — первая точка приёмника `reference_antenna`; курс — по двум антеннам (база
   master → rover 12,4 м вдоль трамвая, работает и на стоянке); место на кольце — проекция
   точки GNSS с учётом курса (пути встречных направлений идут в ~5 м друг от друга).
3. **Далее** положение = место на кольце + пройденный путь по одометрии; координаты x, y, z
   и курс — по карте. Ковариация: вдоль пути растёт с пройденным путём, поперёк — ~0,5 м.
4. **Коррекция**: если в пути приходит точка GNSS (организаторы разрешили использовать редкие
   точки в середине маршрута), место на кольце уточняется фильтром Калмана; выбросы отбрасываются.

Без карты или вне её — путь по прямой от точки выставки по курсу. Точность на 61 обучающем
прогоне 30618 при GNSS только в первые 5 с: средняя ошибка положения — медиана 3,1 м.

Пересборка карты: `python3 tools/build_route_map.py <папка data датасета> src/tram_odometry/config/route_map.csv`.

### Учёт различий трамваев

Датчики пишут скорость колёс в км/ч, но отношение пути по колёсам к пути по GNSS у трамваев
разное (износ и профиль колёс). Масштаб откалиброван по координатам GNSS обучающих прогонов
на надёжных участках (скорость > 10 км/ч, тележки согласны, без скачков GNSS):

| Трамвай | Путь колёс / путь GNSS | Данные |
|---|---|---|
| 30618 | 3,5940 | 60 прогонов, 300 км; разброс по прогонам (квартили) 3,594–3,598 |
| 30639 | 3,6095 | 18 прогонов, 85 км; между днями записи менялся от 3,63 до 3,59 |

Передняя и задняя тележки совпадают в пределах 0,01 %. Трамвай выбирается параметром
`vehicle_id` (по умолчанию `30618`); для другого трамвая масштаб задаётся `wheel_speed_scale`.

## Отличия от файлов организаторов

- `src/tram_vehicle_msgs/package.xml` — добавлен обязательный тег `<maintainer>`: без него
  `colcon build` в Humble завершается ошибкой «Package 'tram_vehicle_msgs' must declare at least
  one maintainer». `CMakeLists.txt` и `msg/*.msg` не изменены.
- Скорость колёс в данных — в км/ч, а не в м/с, как сказано в README датасета (сверено с GNSS:
  отношение ≈ 3,6). Нода переводит её параметром `wheel_speed_scale`.
