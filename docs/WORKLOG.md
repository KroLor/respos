### Эталон на стенде
- master fix status=2 в ENU от **первого фикса master** (любой статус), скорость = |twist| master.
- Фильтр эталона: скачки против скорости колёс + отклонение от скользящей медианы ±1 с >2 м (по горизонтали и **высоте**: в status=2 встречаются скачки высоты на 50+ м) + точки с разреженным окружением (края пропусков). Без этого MAX-метрики положения были завышены до 60 м из-за самого эталона.
- Скорость GNSS: точки, где |v_GNSS − v_колёс| > 1 м/с, считаются сбоями эталона (метрика `v_*` — без них, `v_raw_*` — со всеми).

### Модель и отбраковка (v6–v14)
- Реальный юз в «чистых» данных: `30618_616ec56b` около t=1020 с — колёса за 3.5 с падают с 8.2 м/с до 0 и 2 с стоят, трамвай при этом едет (по GNSS). Есть в данных, хотя редко.
- Проверка «ускорение колеса против модели текущей позиции» давала ложные «юзы» там, где модель неточна (отпуск тормоза, глубокое торможение на малой скорости). Заменена на **проверку против физической огибающей**: ускорение колеса вне диапазона [макс. торможение; макс. тяга] при данной скорости для любой позиции контроллера. Ложных флагов на clean — 0.0 %.
- **−15 тоже неоднозначна:** длительное удержание −15 на ходу встречается в нескольких прогонах (например `30618_74559c73`, 294 точки) при a≈−0.1 — нетипичные ситуации, портящие медиану. Калибровка стала устойчивой: медиана помпрогонных медиан (≥3 прогонов в ячейке).
- **Тормозная характеристика — разделимая физическая модель** a(u,v) = a₀(v) + B(u)·φ(v): уровень торможения позиции × зависимость от скорости (затухание электродинамического торможения на малой скорости). Подгонка ALS с весами √n, B(u) монотонна. Причина: у глубоких позиций данные есть только в части скоростей, табличное заполнение «сплющивало» строки −9…−15 в одно значение.
- Исправлены ошибки логики отбраковки:
  - при инициализации скорости P теряла положительную определённость → `math domain error` на 2 прогонах; исправлено + форма Джозефа в обновлении + try/except в ноде (нода не падает);
  - нода могла стартовать на ходу — первое показание отбраковывалось гейтом (скорость 0); теперь скорость инициализируется первым достоверным показанием;
  - проверка «одиночного скачка» сравнивала с последним **принятым** показанием → развивающийся юз помечался как серия выбросов; теперь сравнение с предыдущим сырым;
  - проверка огибающей выполнялась только для прошедших гейт измерений → эпизод, отбракованный гейтом, не считался подтверждённым, и растущий гейт принимал показание середины восстановления. Теперь огибающая проверяется всегда;
  - откат при подтверждении эпизода: скорость восстанавливается из оценки 0.35–0.6 с назад + модель (первые показания эпизода уже прошли гейт);
  - гистерезис выхода из эпизода: колесо снова принимается, когда его ускорение 0.5 с согласуется с моделью.

### ESN: многошаговое обучение (`bench/esn_multistep.py`, GPU RTX 5070 Ti, PyTorch 2.11 cu128 в .venv)
- Идея: резервуар видит только внешние воздействия (история позиций контроллера и уклона) → его состояния не зависят от прогнозной скорости и считаются один раз; выходной слой обучается градиентом через развёртку модели в замкнутом контуре на 30 с (300 шагов): v ← v + dt·(a_физ + ESN), потери — ошибка скорости (+0.01·ошибка пути) на всём горизонте. Старт весов = 0 (чистая физика), ранняя остановка по внутренней валидации (20 % train-прогонов). 35 тыс. окон, эпоха 3.4 с на GPU, 60 эпох ≈ 4 мин.
- Результат на val (17 прогонов, 676 стартов, тот же код оценки, что в шаге 0):

| горизонт | физика: v / путь | ESN многошаговая (200 нейронов, leak 0.05) | изменение |
|---|---|---|---|
| 5 с | 0.468 / 1.12 м | 0.469 / 1.11 м | ≈ 0 |
| 10 с | 0.643 / 3.64 м | 0.617 / 3.56 м | −4 % / −2 % |
| 30 с | 1.028 / 18.0 м | 0.886 / 15.5 м | **−14 % / −14 %** |

- Устойчиво по конфигурациям: leak 0.02–0.3, вес пути 0.01–0.1 — на 30 с везде 0.87–0.93 м/с против 1.03. Резервуар 500/1000 нейронов почти не лучше (0.871/0.864) — оставляем 200 (дешевле для реального времени).
